## Why CodeOcean, and the capsule layout

Nature's submission system provides CodeOcean for reproducible-code hosting.
Capsules use a fixed top-level layout: `code/`, `data/`, `environment/`,
`metadata/`, plus an internal `.codeocean/`. `environment/` (Dockerfile) and
`metadata/metadata.yml` are auto-generated by CodeOcean's platform once the
environment/capsule metadata is configured through their UI — never hand-author
these, just leave them as empty stubs in the `/nrs` staging copy.

## Workflow pattern (repeat for every new figure notebook)

1. Build/verify the notebook in this repo's `Notebooks/` folder first
   (standalone: only relative paths, no dependency on the rest of the repo or
   absolute `/nrs` paths where avoidable).
2. Write a `Notebooks/src/Fig_<label>_generate_processed_data.py` script that
   reduces the real raw/intermediate data down to just what the final plot
   needs, saved to `Notebooks/processed_data/Fig_<label>_....npz` (or `.csv` if
   the source data has no known reproducible generation script — carry it over
   as-is and document that in the notebook markdown).
3. Re-run the notebook via `jupyter nbconvert --to notebook --execute --inplace`
   after any change, and check cell outputs/errors programmatically (parse the
   `.ipynb` JSON) rather than trusting "no exception thrown" — confirm
   image/error counts match expectations.
4. Use `plt.show()`, never `plt.savefig()` — figures render inline in these
   notebooks, there's no `results/` folder in use.
5. When display parameters (transform/colormap/vmin/vmax) differ between
   plausible source notebooks, ASK rather than guess — this happened
   repeatedly for `Figure_2bcdf_4f_brain_map.ipynb` and `Figure_4cd_...ipynb`,
   and the "obvious" choice was wrong each time.
6. Once satisfied, run `Notebooks/sync_to_compiled.sh` (rsyncs `Notebooks/` →
   `compiled_data_codes/code/` + `data/processed_data/`, rewrites
   `processed_data/...` paths to `../data/processed_data/...` for the
   code/data split, leaves `raw_data/` untouched) then re-execute the synced
   copies from `/nrs` to confirm they still work post-rewrite.
7. Keep `Notebooks/processed_data/` on local disk — don't delete it after
   syncing. It's gitignored either way, so it never hits the repo; only clean
   it up if explicitly asked to at that point (deleting it right after sync
   broke re-opening notebooks in VS Code more than once).
8. Only `.py` files under `Notebooks/src/` are git-trackable — `*.ipynb`,
   `*.csv` (outside `Datalists/`), `*.npy`/`*.npz`, `*.pdf` are all gitignored
   repo-wide. Commit + push just the `.py` scripts.
9. `Notebooks/additional/` holds unsorted/internal-record-only analyses that
   should NOT be part of the capsule — `sync_to_compiled.sh` explicitly
   excludes this folder by name. Anything meant for the actual CodeOcean
   submission goes directly under `Notebooks/` (or `Notebooks/src/`), never
   in `additional/`.
10. `Notebooks/old_figure_panels/` (added 2026-07-28) is excluded the same
    way — obsolete figure-panel `.py` scripts kept in git as a historical
    record, not synced to the capsule. Unlike `additional/`, these files ARE
    git-tracked. When adding any new "don't sync" folder under `Notebooks/`,
    add it to `sync_to_compiled.sh`'s exclude list and verify with an actual
    sync run.

## Notebooks built so far

- **`Figure_1h_average_diff_dynamics_epochs.ipynb`** — average dFF dynamics
  across epochs for one example fish. Generation script computes
  `dFF_epochs`/`CL_trial`/`cells_center`/`p_mat`/`sign_mat` from Fish1's raw
  data. Ported from `Encoding/Figure_3_average_diff_dynamics_epochs.ipynb`.
- **`Figure_1i_fraction_diff_cells.ipynb`** — fraction of modulated cells over
  time, from a small pre-existing `Encoding/data_fraction_cells.csv` with no
  known generation script (carried over as-is). Ported from
  `Encoding/Figure_1i_fraction_diff_cells.ipynb`.
- **`Figure_2bcdf_4f_brain_map.ipynb`** — brain-map panels for Fig 2b, 2c, 2d,
  2f, and 4f. Panel mapping: **2b**=pulse-position-responsive cells,
  **2c**=integrative cells positive (masked to pulse-pos voxels),
  **2d**=pulse-position-suppressed cells, **2f**=motor-responsive cells
  positive, **4f**=motor-responsive cells negative. `int_neg` is NOT part of
  this figure (dropped entirely). Sources:
  `Clusters/depreciated/Figure_3_brain_maps/Figure_3_pulse_integrative_cell_corr_map_v1.ipynb`
  (pulse/int panels) and
  `Clusters/depreciated/Figure_3_brain_maps/brain_clusters_af_motor_v2.ipynb`
  (motor panels).
  - Display conventions per panel (each contested/corrected at least once —
    trust these over re-deriving from source notebooks blind): 2b = `sqrt`
    transform, `cmap='hot'`, `vmax=sqrt(0.8), vmin=0.01`. 2c =
    `np.percentile(...,99)`, `cmap='nipy_spectral'`, `vmax=4, vmin=-0.1`. 2d =
    linear (no sqrt), `cmap='hot'`, `vmax=0.4, vmin=0.24`, no atlas
    background. 2f = linear, `cmap='hot'`, `vmax=0.7, vmin=0`. 4f = linear,
    `cmap='hot'`, `vmax=0.5, vmin=0`.
  - `Fig_2bcdf_4f_generate_pulse_maps.py` / `_generate_motor_maps.py` document
    how the raw whole-brain `.npy` volumes (~4.9GB each) are derived, one
    level upstream of `Fig_2bcdf_4f_generate_processed_data.py`. Written but
    **never executed** — not needed since the volumes already existed from an
    earlier, separate run. The pulse-maps script deliberately diverges from
    `brain_clusters_af_pulse.ipynb`'s own positive-map cells, which reload
    `result_tmp` from the already-saved file right after computing it fresh,
    then just re-save the reload (looks like leftover interactive-session
    behavior, not intentional) — this script saves the fresh computation
    directly instead.
- **`Figure_4cd_neural_prediction_swim.ipynb`** — Fig 4c (whole-brain map of
  cells anti-correlated with recovery-swim-onset timing) + Fig 4d (per-fish
  GradientBoostingRegressor neural-activity → swim-onset-time prediction,
  scatter colored by CL/OL). Sources:
  `Clusters/depreciated/Figure_5_swim_predictor/neural_prediction_swim.ipynb`
  (4c) and `neural_prediction_swim_timing.ipynb` (4d). Unlike the 2bcdf/4f
  maps, this whole-brain map **was** actually built and executed
  (`Fig_4cd_generate_processed_data.py`, ~10 min run), because its per-fish
  correlation inputs (`cell_corr_recovery_swim_time.npz`) were already cached
  at each fish's original `save_dir` — only ~49k significant cells needed the
  atlas-shaped accumulation step.
  - Fig 4c display: no atlas background, `cmap='hot'`, `vmax=0.3, vmin=0`.
  - Fig 4d display: scatter `resp_est` vs `resp`, black=CL/red=OL, dashed
    identity line, axes 0–15s.
- **`Figure_2bcdf_activity_plot.ipynb`** — for each of Fig 2b/2c/2d/2f, a
  CL+OL activity heatmap (cells sorted by pulse/int/motor correlation)
  followed by a CL (black) vs OL (red) trial-averaged trace (mean±sem).
  Sources: `Notebooks/additional/Figure_2_brain_dynamics/Figure_2_brain_clusters_af_pulse_v2.ipynb`
  (2b/2c/2d — loads two small precomputed caches, no raw per-fish data
  needed) and `Figure_2_ex_motor_dynamics_v1.ipynb` (2f — needs one example
  fish's raw trial data, row 2 in the datalist).
  - Flagged, not resolved: the 2d (pulse-neg) trace's cell-selection
    threshold, ported verbatim (`pulse_r < 0.05`), is far weaker than the
    brain map's own `pulse_r < 0` cutoff — selects ~55% of all cells rather
    than a clean negative subset. Still produces a visible CL-trial
    suppression dip, not obviously broken, but worth a second look.
